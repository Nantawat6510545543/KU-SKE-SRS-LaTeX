\chapter{Software Architecture Design}
\label{ch:software-architecture-design}

\noindent
This chapter presents the software architecture that supports reproducible EEG experimentation in this project. It describes a layered architecture, the main execution flow, the AI processing pipeline, and the key data schemas used to make runs traceable and repeatable.
\vspace{1em}

\section{Software Architecture}
\label{sec:software-architecture}

The system is designed using a \textbf{layered client–server architecture}, consisting of a React-based frontend and a FastAPI backend. The backend is implemented as a modular monolith, where functionalities are organized into domain-specific modules such as API handling, data processing, visualization, and machine learning.
\vspace{0.5em}

At its core, the system follows a \textbf{pipeline-oriented architecture}, where EEG data is processed through sequential stages (e.g., preprocessing, epoch extraction, and feature generation). This structure enables reproducibility and flexible recomputation when parameters change.

\section{Design Patterns}
\label{sec:design-patterns}

To ensure a modular and extensible architecture capable of handling high-throughput data, the following design patterns were implemented:
\vspace{0.5em}

\begin{itemize}[leftmargin=*]
    \item \textbf{Pipeline Pattern:} EEG processing workflow
    \item \textbf{Facade Pattern:} API endpoints
    \item \textbf{Strategy Pattern:} parameter-driven behavior
    \item \textbf{Factory Pattern:} model instantiation
    \item \textbf{Registry Pattern:} task preprocessor selection
    \item \textbf{Observer Pattern:} WebSocket progress updates
    \item \textbf{Repository Pattern:} structured EEG cache
    \item \textbf{Composite Pattern:} Pipeline Session is a combination of schemas
\end{itemize}

\section{Domain Model}
\label{sec:domain-model}

The domain model of the proposed EEG analysis platform represents the key entities and their relationships within the system. The design focuses on supporting a structured workflow for EEG data analysis and machine learning experimentation.
\vspace{0.5em}

The central entity in the system is the \textbf{Dataset}, which represents EEG data organized in BIDS format. Each dataset consists of multiple \textbf{Subjects}, where each subject contains EEG recordings and associated metadata for specific tasks.
\vspace{0.5em}

The \textbf{User} interacts with the system to perform analysis operations on the dataset. These operations include signal inspection, preprocessing, dataset construction, and model training.
\vspace{0.5em}

A \textbf{PipelineSession} entity represents the sequence of preprocessing operations applied to EEG data. This includes filtering, resampling, artifact removal, and epoching. The pipeline operates on raw EEG signals and produces processed outputs such as prefiltered signals, cleaned data, and epochs.
\vspace{0.5em}

To improve efficiency, the system incorporates a caching mechanism that stores intermediate results. These cached outputs are associated with specific subjects and parameter configurations, allowing the system to reuse previously computed results and reduce redundant processing.
\vspace{0.5em}

The \textbf{AI Model} entity represents machine learning models used for experimentation. Models can be trained using processed datasets and evaluated using standard performance metrics.
\vspace{0.5em}

Overall, the domain model reflects a modular structure where data processing, visualization, and machine learning components are integrated into a unified workflow.

\section{Design Class Diagram}
\label{sec:design-class-diagram}

The system architecture follows a layered design, where different components are organized based on their responsibilities. The main modules correspond to the backend structure implemented using FastAPI.
\vspace{0.5em}

At the top level, the \textbf{API layer} (app/api/endpoints) handles incoming requests from the frontend. It defines endpoints for operations such as data loading, preprocessing, visualization, and model training. This layer acts as the interface between the user interface and the backend system.
\vspace{0.5em}

The \textbf{Schema/DTO layer} (app/schemas) defines structured data models used for request validation and response formatting. This includes parameter schemas for preprocessing configurations and UI-related data representations.
\vspace{0.5em}

The \textbf{Core module} (app/core) manages configuration and dataset loading. It is responsible for accessing EEG data from BIDS-formatted directories and preparing it for further processing.
\vspace{0.5em}

The \textbf{Pipeline module} (app/pipeline) implements the core EEG processing logic. It receives raw EEG data and applies preprocessing steps such as filtering, resampling, and epoching. This module also interacts with the caching mechanism to store and retrieve intermediate results.
\vspace{0.5em}

The \textbf{Visualization module} (app/plots) contains submodules for different types of outputs:

\begin{itemize}[leftmargin=*]
    \item \textbf{plot:} single-view signal visualization 
    \item \textbf{grid plot:} comparative visualization
    \item \textbf{data:} tabular data summaries
    \item \textbf{ai:} model-related results and metrics 
\end{itemize}

These modules generate outputs that are returned to the frontend for display.
\vspace{0.5em}

The \textbf{AI Model module} (app/ai\_models) defines machine learning models used within the platform. These models can be trained and evaluated using processed datasets.
\vspace{0.5em}

Additionally, the system maintains a \textbf{job/output storage structure} (jobs/ai/train/...) that stores training results, logs, and model artifacts, along with the cache for each pipeline step in \textbf{eegcache} folder (such as prefiltered, cleaned, epochs, etc.) While not a full asynchronous job system, this structure supports persistence and traceability of preprocessing and model training runs.
\vspace{0.5em}

This modular design ensures separation of concerns, making the system maintainable, extensible, and aligned with the research workflow.

\section{Sequence Diagram}
\label{sec:sequence-diagram}

\subsection{Experiment Execution Flow}
\label{subsec:realtime-tracking-process}
\textbf{Scenario: Run an experiment}
\begin{enumerate}
    \item The user selects a subject and task from the Web UI.
    \item The Web UI sends an experiment-run request with parameters to the Backend API.
    \item The Backend API requests the Pipeline to load EEG and event metadata, then returns a quick validation summary to the UI.
    \item The user confirms the run after reviewing the validation summary.
    \item The Backend API triggers preprocessing and epoch construction in the Pipeline.
    \item The Pipeline builds features and forwards data to the AI Trainer for training and validation.
    \item The trainer returns metrics and predictions, artifacts are persisted in the Result Store, and the UI displays the run summary (plots and model scores).
\end{enumerate}

\section{Pipeline}
\label{sec:pipeline}

\subsection{AI Processing Pipeline}
\label{subsec:ai-processing-pipeline}

The AI processing pipeline is designed to enforce traceability. Each stage consumes explicit inputs and produces versioned outputs:
\begin{enumerate}
    \item \textbf{Ingestion:} load CCD runs and parse events/metadata.\footnote{\cite{hbn_fair_2024}.}
    \item \textbf{Trial construction:} extract fixed-length ITI windows and attach labels.
    \item \textbf{Preprocessing:} filter, normalize, mitigate artifacts, and create epochs.
    \item \textbf{Verification:} compute SNR spectra and related plots for steady-state validation.
    \item \textbf{Features:} compute ITI-derived features (e.g., spectral power at stimulation frequencies/harmonics).
    \item \textbf{Modeling:} train RT regressors and correctness classifiers.
    \item \textbf{Evaluation:} compute metrics and export artifacts for reporting.
\end{enumerate}
