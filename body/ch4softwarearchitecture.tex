\chapter{Software Architecture Design}
\label{ch:software-architecture-design}

\noindent
This chapter presents the software architecture that supports reproducible EEG experimentation in this project. It describes a layered architecture, the main execution flow, the AI processing pipeline, and the key data schemas used to make runs traceable and repeatable.
\vspace{1em}

\section{Software Architecture}
\label{sec:software-architecture}

The architecture reflects a research workflow tailored to the EEG2025 challenge: behavioral prediction using CCD-ITI segments. To keep the codebase maintainable and to separate concerns, the system is organized into layers.

\subsection{API Layer (Presentation)}
\label{subsec:api-layer}
This layer provides user-facing interaction points (UI actions and/or API endpoints) such as selecting subjects, triggering dataset construction, running training, and exporting results. It contains minimal domain logic and delegates work to the service layer.

\subsection{Service Layer (Application Logic)}
\label{subsec:service-layer}
This layer orchestrates workflows: loading CCD runs, constructing ITI windows, executing preprocessing and feature extraction, training models, running evaluation, and producing report artifacts (plots/tables). It also coordinates caching and logging so that runs are reproducible.

\subsection{Infrastructure Layer (Data Access)}
\label{subsec:infrastructure-layer}
This layer handles I/O and integration with external resources, including reading BIDS-formatted HBN-EEG files, caching intermediate artifacts, and persisting run outputs.

\subsection{Domain/Model Layer}
\label{subsec:domain-layer}
This layer contains the core domain concepts (trial windows, feature tables, experiment configurations, metrics) and the algorithms that operate on them.

\section{Sequence Diagram}
\label{sec:sequence-diagram}

\subsection{Experiment Execution Flow}
\label{subsec:realtime-tracking-process}
\textbf{Scenario: Run an experiment}
\begin{enumerate}
    \item Select subjects/sessions and the CCD task.
    \item Load BIDS/HED events and construct CCD-ITI windows with aligned RT and correctness labels.
    \item Apply a fixed preprocessing configuration to the ITI epochs.
    \item Compute verification plots (e.g., SNR spectra) to confirm steady-state characteristics.
    \item Extract features and train models for RT regression and correctness classification.
    \item Evaluate using standard metrics and export a run summary (configs, metrics, and plots).
\end{enumerate}

\section{Pipeline}
\label{sec:pipeline}

\subsection{AI Processing Pipeline}
\label{subsec:ai-processing-pipeline}

The AI processing pipeline is designed to enforce traceability. Each stage consumes explicit inputs and produces versioned outputs:
\begin{enumerate}
    \item \textbf{Ingestion:} load CCD runs and parse events/metadata.\footnote{\cite{hbn_fair_2024}.}
    \item \textbf{Trial construction:} extract fixed-length ITI windows and attach labels.
    \item \textbf{Preprocessing:} filter, normalize, mitigate artifacts, and create epochs.
    \item \textbf{Verification:} compute SNR spectra and related plots for steady-state validation.
    \item \textbf{Features:} compute ITI-derived features (e.g., spectral power at stimulation frequencies/harmonics).
    \item \textbf{Modeling:} train RT regressors and correctness classifiers.
    \item \textbf{Evaluation:} compute metrics and export artifacts for reporting.
\end{enumerate}

\section{Schemas}
\label{sec:schemas}

To support reproducibility and consistent reporting, the system uses a small set of explicit schemas (conceptual data structures):
\begin{itemize}
    \item \textbf{ExperimentConfig:} dataset filters, preprocessing parameters, feature settings, model hyperparameters, and split strategy.
    \item \textbf{TrialWindow:} subject/session identifiers, ITI start/end, and behavioral labels (RT and correctness).
    \item \textbf{FeatureTable:} feature matrix with consistent column definitions and provenance metadata.
    \item \textbf{MetricReport:} regression and classification metrics, plus links to generated plots.
\end{itemize}

\section{AI Component}
\label{sec:ai-component}

The AI component is responsible for mapping CCD-ITI features to behavioral targets. It is integrated as a service-layer workflow that consumes a dataset definition and a configuration, then produces predictions and evaluation artifacts.

\begin{itemize}
    \item \textbf{Targets:} RT (regression) and correctness (binary classification).
    \item \textbf{Evaluation:} MAE/MSE for RT; accuracy, F1-score, precision, and recall for correctness.
    \item \textbf{Best practices:} subject-independent evaluation when possible, explicit logging of splits/filters, and verification plots to avoid interpreting spurious results.
\end{itemize}

Detailed AI design choices (canvas, model development, UX integration, and deployment strategy) are presented in Chapter~\ref{ch:ai-component-design}.
