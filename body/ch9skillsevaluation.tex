\chapter{Knowledge and Skills Evaluation}
\label{chap:knowledge-skills-evaluation}

\noindent
This chapter evaluates the knowledge and skills developed throughout the project by comparing
them with the Program Learning Outcomes (PLOs) and the expected rubric levels established
by the curriculum. The evaluation is conducted from three perspectives: AI-based assessment,
student self-assessment, and advisor assessment. The purpose of this chapter is not only to
measure achievement, but also to provide reflective insight into how different evaluative
perspectives reveal strengths, gaps, and opportunities for further development.

\section{Comparison Between Program Targets and AI-Based Evaluation}
\label{sec:plo-ai-evaluation}

The first part focuses on comparing the program's expected learning outcomes with the
evaluation generated by AI. The AI assigns an evaluation level for each dimension and provides
justification explaining why each level was assigned.

\subsection{Executive Summary}
\label{subsec:ai-executive-summary}

This project demonstrates a strong integration of software engineering and AI experimentation
practices, particularly in building a reproducible EEG analysis platform. The student shows
clear competency in system design, pipeline engineering, and experimental rigor, but limited
success in achieving strong AI model performance.

Overall, the student meets most intended graduate outcomes for an undergraduate Software
Engineering program, especially in structured system design, reproducibility, experimentation
workflows, and technical communication. However, gaps remain in advanced AI effectiveness
and system scalability, preventing full alignment with higher-level expectations in some
dimensions.

\subsection{Justification for Each Dimension}
\label{subsec:ai-justification}

\subsubsection{Software Development \& Programming — Level 3 (Exceeds Expectations)}

The AI assigned Level~3 based on the following evidence:
\begin{itemize}
    \item The system uses a layered architecture (React + FastAPI + pipeline design), demonstrating modular design.
    \item Implementation includes multiple design patterns (Pipeline, Strategy, Factory, Registry, Observer), indicating architectural maturity.
    \item The system supports caching, reproducibility, and parameter-driven execution, aligning with scalable engineering practices.
    \item Use of Docker deployment and a hybrid architecture (cloud and local backend) shows real-world system considerations.
    \item Presence of traceability, logging, and job artifacts reflects evaluation-driven development.
\end{itemize}

Level~4 was not assigned because there is no evidence of large-scale production deployment,
DevOps pipelines, or organizational engineering standards. The system does not address
concerns such as security, high availability, or distributed orchestration.

\subsubsection{Machine Learning, LLM \& AI Systems — Level 2 (Below Expectations)}

The AI assigned Level~2 based on the following evidence:
\begin{itemize}
    \item The student builds task-specific ML pipelines for reaction time regression and correctness classification.
    \item Proper evaluation metrics are used (MAE, R\textsuperscript{2}, F1, balanced accuracy).
    \item Data splitting strategies (subject-independent) are implemented to avoid leakage.
    \item Class imbalance is addressed using weighting and sampling techniques.
    \item A reproducible ML experimentation workflow with logging and validation is established.
\end{itemize}

Level~3 was not assigned because there is no evidence of production ML systems,
monitoring or observability, model lifecycle management, or automated pipelines (MLOps).
Furthermore, model performance remains weak (R\textsuperscript{2} $\approx$ 0, imbalance
issues unresolved), and no advanced architectures or optimization strategies were explored in depth.

\subsubsection{Data Management \& Knowledge Systems — Level 3 (Exceeds Expectations)}

The AI assigned Level~3 based on the following evidence:
\begin{itemize}
    \item Structured data pipelines are implemented from raw EEG through processed data to features.
    \item Caching with parameter hashing and pipeline versioning is used.
    \item Traceability is ensured via job specifications, logs, and reproducible outputs.
    \item Cohort filtering and multi-subject analysis support scalable data handling.
    \item Data integrity checks, including label alignment validation and fail-fast mechanisms, are maintained.
\end{itemize}

Level~4 was not assigned because there are no enterprise-level features such as federated
systems, policy-based governance, or cross-system integration.

\subsubsection{Critical \& Creative Thinking — Level 3 (Meets Expectations)}

The AI assigned Level~3 based on the following evidence:
\begin{itemize}
    \item An explicit hypothesis-driven approach is used: predicting behavior from prestimulus EEG.
    \item An iterative refinement process is applied, including fixing trial alignment, improving preprocessing, and adjusting splits.
    \item Strong emphasis is placed on validation before modeling (SNR verification).
    \item Failure modes are clearly identified, including regression collapse and class imbalance.
    \item Reflective analysis acknowledges limitations and future work.
\end{itemize}

Level~4 was not assigned because there is no evidence of novel methodology or new
research contributions, and no new frameworks or significantly innovative solutions are proposed.

\subsubsection{Collaboration \& Communication — Level 3 (Meets Expectations)}

The AI assigned Level~3 based on the following evidence:
\begin{itemize}
    \item The report is well-structured and comprehensive, covering requirements, design, implementation, and evaluation.
    \item Traceability between user stories and requirements is included.
    \item Technical risks and limitations are clearly communicated.
    \item Detailed diagrams, tables, and system explanations are provided.
    \item Alignment between system design and research goals is demonstrated.
\end{itemize}

Level~4 was not assigned because there is no evidence of leading teams, cross-disciplinary
coordination, or influencing broader communities.

\subsection{AI Final Conclusion}
\label{subsec:ai-final-conclusion}

\textbf{Strengths identified by the AI evaluation:}
\begin{itemize}
    \item Strong software engineering foundation with modular, scalable architecture.
    \item Excellent reproducibility and traceability practices.
    \item Rigorous experimental methodology and critical reasoning.
    \item Clear and structured technical communication.
\end{itemize}

\textbf{Limitations identified by the AI evaluation:}
\begin{itemize}
    \item Weak AI model performance and optimization.
    \item Limited exploration of advanced ML techniques or architectures.
    \item No evidence of production-grade ML systems (MLOps).
\end{itemize}

The student is well-prepared for roles in software engineering and AI system development,
particularly in research engineering, data pipeline design, and experimentation platforms.
Further development is needed in advanced machine learning techniques and model performance
optimization.

\subsection{Reflection on the AI Evaluation}
\label{subsec:reflection-ai}

Overall, we agree with most parts of the AI evaluation, especially the comments on software
architecture, reproducibility, and technical communication. However, we believe the Machine
Learning score may be somewhat conservative when interpreted without project context.

Our work attempts a difficult and less explored objective: predicting behavioral outcomes from
prestimulus EEG signals in a CCD setting. This problem has a high uncertainty level and
substantial research and engineering risk. It often requires longer research timelines in
graduate-level contexts, whereas this project was conducted at undergraduate level within less
than one year. As a result, substantial effort was required to build reliable data alignment,
preprocessing, and leakage-safe evaluation before meaningful model training was possible.

As a result, a significant portion of project time was invested in foundational research
engineering work that is not always visible through final model metrics alone. In particular,
we prioritized trial-label integrity, subject-independent splits, and reproducible experiment
tracking to ensure that any conclusion is scientifically valid. These are essential requirements
for trustworthy AI experimentation, even when predictive performance remains limited.

Therefore, we accept that the current model performance has not yet reached the target level,
but we also argue that the project demonstrates strong competence in designing and executing
an end-to-end AI experimentation framework for a challenging novel problem. In this sense,
the main limitation is outcome maturity, not lack of methodological rigor or effort.

\subsection{Reflection on Self-Evaluation Compared with AI Evaluation}
\label{subsec:reflection-self}

Our self-evaluation is generally consistent with the AI assessment in recognizing strong
performance in software engineering, data pipeline design, and technical communication.
In particular, we agree that this project demonstrates structured architecture, reproducible
experimentation, and clear traceability from problem definition to evaluation outputs.

The main difference is in how the Machine Learning dimension is interpreted. The AI rates this
dimension lower because the final predictive performance is still limited, and we accept that
result from an outcome perspective. However, from our perspective, this rating does not fully
reflect the difficulty and novelty of the chosen problem. Our project focuses on prestimulus EEG
behavior prediction in a CCD setting, which is a high-uncertainty task with substantial research
and engineering risk. This type of work commonly requires multi-year depth in graduate-level
research contexts, whereas this project was conducted at undergraduate level within a timeline
of less than one year.

Because of that challenge, substantial project time was invested in foundational research
engineering work before model optimization could be done effectively. This includes strict
trial-label alignment, leakage-safe subject-independent splitting, quality checks for signal
validity, and reproducible experiment tracking. These steps are essential for trustworthy
ML experimentation, but they reduce the time available for broader architecture exploration
and extensive hyperparameter optimization.

For this reason, our self-evaluation remains Level~3 across all dimensions, reflecting confidence
in the rigor of the development and experimentation process, while still acknowledging that
Machine Learning outcomes have not yet reached the desired performance level. In summary,
the gap is more about model maturity than lack of technical capability or effort.
