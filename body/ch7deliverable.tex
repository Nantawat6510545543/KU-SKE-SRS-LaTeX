\section{Software Solution}
\label{sec:software-solution}

The proposed system is an interactive EEG analysis platform designed to support data exploration, preprocessing, visualization, and machine learning experimentation within a unified interface. The platform is developed to address inefficiencies in traditional notebook-based workflows by providing a structured and parameter-driven environment for EEG analysis.

For more, please refer to our \textbf{Github:}

	[Link: https://github.com/Nantawat6510545543/senior-project] for the web platform development, and
	\vspace{0.5em}

	[Link: https://github.com/Nantawat6510545543/eeg2025-Vistec] for the model training development.


\subsection{System Overview}
\label{sec:system-overview}
The platform follows a research-oriented workflow where users first inspect signals before executing machine learning models.
To support this process, the interface uses a \textbf{mode-action} structure, and additionally provides flexible 
\textbf{subject selection and filtering} to accommodate both single-subject inspection and cohort-level analysis.

\subsection{Input Configuration}
\label{sec:input-configuration}

Users can choose between two primary input types:
\begin{itemize}
    \item \textbf{Single Subject:} 
    \begin{itemize}
        \item User selects an individual participant and task.
        \item All mode actions are executed for the selected subject only.
        \item This mode is ideal for detailed inspection or troubleshooting of individual EEG recordings.
    \end{itemize}
        \item \textbf{Cohort Filter (Meta Filter):} 
    \begin{itemize}
        \item User defines filters across attributes: sex, age range, attention, internalizing/externalizing scores, CCD accuracy, response time.
        \item Optional ``Per Subject'' toggle for applying filters individually or collectively.
        \item This mode enables exploratory data analysis and large-scale EEG studies without manual participant selection.
    \end{itemize}
\end{itemize}

In both cases, the selected input determines the scope of subsequent operations.

\subsection{Mode-Based Interaction}
\label{sec:mode-based-interaction}

The platform organizes functionality into four primary operational modes:

\begin{itemize}
	\item \textbf{Plot Mode:} Provides detailed visualization of EEG signals. This mode supports both single-subject and cohort-based data, enabling focused signal inspection.
    \item \textbf{Grid Plot Mode:} Enables comparative visualization across multiple subjects, conditions, or cohorts using structured layouts.
    \item \textbf{Data Mode:} Presents structured tabular representations of EEG data and derived results, allowing users to inspect intermediate outputs.
	\item \textbf{AI Mode:} Supports machine learning experimentation, including dataset preparation, model training, and evaluation.
\end{itemize}

Each mode dynamically exposes relevant actions, allowing users to interact with the system in a structured and context-aware manner.

\subsection{Action Selection}
\label{sec:action-selection}

Each operational mode in the platform exposes a set of actions that correspond to specific functionalities. These actions are organized within their respective mode (Plot, Grid Plot, Data, AI), enabling users to interact with the system in a structured manner.

\begin{description}
    \item[Plot Mode Actions] \hfill \\
    Provides detailed visualization of EEG signals. Available actions include:
    \begin{itemize}
        \item \textbf{Evoked} – Visualizes averaged evoked responses for individual conditions or overall.
        \item \textbf{Frequency} – Generates frequency-domain representations of EEG signals.
        \item \textbf{Sensors} – Displays the spatial arrangement and activity of EEG sensors.
        \item \textbf{SNR} – Computes and visualizes the signal-to-noise ratio across channels.
        \item \textbf{Time Domain} – Shows EEG signal waveforms in the time domain.
        \item \textbf{Epochs} – Visualizes segmented epochs of EEG data.
        \item \textbf{Evoked Joint} – Combines multiple evoked responses into a single visualization.
        \item \textbf{Evoked Per Condition} – Displays evoked responses separately for each experimental condition.
        \item \textbf{Evoked Topography} – Maps spatial topography of evoked responses across electrodes.
    \end{itemize}

    \item[Grid Plot Mode Actions] \hfill \\
    Enables comparative visualization across multiple subjects or conditions:
    \begin{itemize}
        \item \textbf{Evoked Grid} – Arranges evoked responses for multiple subjects in a structured grid.
        \item \textbf{PSD Grid} – Displays power spectral density comparisons across subjects or conditions.
        \item \textbf{SNR Grid} – Shows signal-to-noise ratio comparisons for multiple subjects in a grid layout.
    \end{itemize}

    \item[Data Mode Actions] \hfill \\
    Provides tabular inspection of EEG data and derived metrics:
    \begin{itemize}
        \item \textbf{EEG Table} – Presents raw or preprocessed EEG data in tabular form.
        \item \textbf{Epochs Table} – Displays segmented EEG epochs and associated metadata.
        \item \textbf{Metadata} – Shows participant and recording metadata in a structured table.
    \end{itemize}

    \item[AI Mode Actions] \hfill \\
    Supports machine learning experimentation, including dataset preparation and model evaluation:
    \begin{itemize}
        \item \textbf{Build Dataset} – Prepares and visualizes the training dataset for machine learning models.
        \item \textbf{Model Summary} – Displays architecture and parameters of the selected AI model.
        \item \textbf{Show Train EEG} – Executes training routines on EEG data and presents training metrics in a structured table.
    \end{itemize}
\end{description}

\subsection{Execution and Logging}
\label{sec:execution-and-logging}

The platform executes user-selected operations in a synchronous manner. During execution, an execution \textbf{Log Panel} is displayed, providing real-time feedback on system operations such as data loading, preprocessing steps, and plot generation.

\vspace{0.5em}
To improve efficiency, the system implements a \textbf{caching mechanism}. Intermediate results, including prefiltered signals, cleaned data, and epochs, are stored based on subject and parameter configurations. When the same configuration is reused, the system retrieves cached results instead of recomputing them.

This approach reduces redundant computation and supports faster iteration during analysis.

\vspace{0.5em}
The platform presents outputs directly within the interface. Visualization results are rendered as plots, while structured outputs are displayed as tables.

\subsection{System Characteristics}
\label{sec:system-characteristics}

The developed platform demonstrates the following characteristics:

\begin{itemize}
	\item \textbf{Interactive:} Enables real-time configuration and execution of analysis tasks
	\item \textbf{Reproducible:} Maintains explicit parameter configurations and execution logs
	\item \textbf{Efficient:} Reduces redundant computation through caching mechanisms
	\item \textbf{Flexible:} Supports both single-subject and cohort-level analysis
	\item \textbf{Integrated:} Combines preprocessing, visualization, and machine learning in a unified system
\end{itemize}

\vspace{1em}
\textbf{Feedback Loop:}
inspect → adjust → train → evaluate → compare → refine

Researchers can iteratively adjust dataset configurations,rerun experiments, and retrain models without rewriting scripts or managing computing environments. This significantly shortens the experimental cycle compared to notebook-based pipelines.

\section{Test Report}
\label{sec:test-report}

This section describes the testing approach used to evaluate the correctness and reliability of the proposed EEG analysis platform. The evaluation focuses on functional verification, reproducibility, and system behavior under typical usage scenarios.

\subsection{Testing Approach}

The system was tested using a functional testing approach, where each core component was evaluated independently and as part of the overall workflow. The testing process focuses on verifying that user actions produce correct outputs and that the system behaves consistently across repeated executions.

\vspace{0.5em}
Testing was performed through manual interaction with the user interface, covering different operational modes and configurations. This approach ensures that the system supports the intended research workflow and that all features are accessible and usable.

\subsection{Functional Testing}
\label{sec:functional-testing}

Functional testing was conducted to verify that each system component operates as expected under standard usage conditions. The primary objective of the development was to validate the ``Expected usage scenario''---ensuring that the core research workflow from data loading to machine learning execution functions correctly for valid, expected inputs.

The testing process focused on verifying that user actions produce correct visual and tabular outputs, and that the system behaves consistently across repeated executions. To systematically evaluate this, a core suite of functional test cases was executed covering the platform's primary operational modes. The specific scenarios and their outcomes are summarized in Table \ref{tab:functional-test-cases}.

While all core functionalities were confirmed to operate correctly under these expected usage conditions, it is important to note the boundaries of this initial evaluation. Because the current testing protocol focused heavily on functional verification of the primary research workflow, future iterations of the software will require expanded edge-case and robust error-handling testing. This includes managing corrupted raw files, handling missing condition markers without system failure, and mitigating out-of-memory errors for exceptionally large cohorts.

\subsection{Reproducibility Testing}
\label{sec:reproducibility-testing}

Building upon the functional tests (specifically TC-06), the system was further evaluated for reproducibility by executing identical configurations multiple times. Results were consistently stable across runs, confirming that:

\begin{itemize}
    \item Parameter configurations are strictly adhered to and applied uniformly.
    \item Cached results are reused appropriately, preventing redundant state changes.
    \item Visual and tabular outputs remain entirely stable across repeated executions of the same pipeline.
\end{itemize}

\subsection{Machine Learning Evaluation Testing}
\label{sec:machine-learning-evaulation-testing}

The platform supports basic machine learning experimentation through its AI mode, and only have loss.
While the app interface currently focuses on the regression metrics (loss, MAE, RMSE, and R²), the underlying model has undergone extensive evaluation, including

\begin{itemize}
	\item \textbf{CCD-ITI approach:} Train on CCD-ITI segments and evaluate under a defined split strategy (preferably subject-independent).
	\item \textbf{Regression metrics (RT):} loss, MAE, RMSE, and R².
	\item \textbf{Classification metrics (correctness):} accuracy, balanced accuracy, sensitivity, and specificity.
	\item \textbf{Verification:} Use SNR spectra (and related plots) to confirm steady-state characteristics before interpreting model outcomes.
\end{itemize}

\subsection{Classification Runs}
\label{subsec:classification-failure-summary}

This section compares the effects of various data balancing strategies on classification performance

\begin{table}[H]
\centering
\begin{tabular}{|l|c|c|c|c|}

None & 0.729 & 0.501 & 0.993 & 0.009 \\
\hline
Class Weight & 0.604 & 0.544 & 0.674 & 0.414 \\
\hline
Weighted Sampler & 0.629 & 0.543 & 0.729 & 0.358 \\
\hline
Undersample & 0.652 & 0.537 & 0.787 & 0.287 \\
\hline
\end{tabular}
\caption{Selected classification runs from W\&B export.}
\label{tab:classification-failure-summary}
\end{table}

\noindent
\textbf{Interpretation:} None shows majority-class collapse (almost all predictions biased to the positive class). Class Weight achieves better balance but still exhibits class-bias and limited generalization. Weighted Sampler helps recall but sacrifices specificity. Undersample improves minority exposure, though instability and false-positive pressure remain.

\noindent
\textbf{Interpretation:} MAE shows low explanatory power with predictions remaining close to average RT.
