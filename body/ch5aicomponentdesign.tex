\chapter{AI Component Design}
\label{ch:ai-component-design}

\noindent
This chapter describes how the AI component is integrated into the overall system workflow, from dataset construction and signal verification to model training and evaluation. It follows an AI-canvas-style requirement analysis, documents model development and evaluation, and describes how the user experience and deployment support reproducible experiments.
\vspace{1em}

\label{sec:business-context}

\vspace{1em}
\noindent\textbf{Diagram Explanation:}
The system is designed as an experimental EEG research platform integrating signal visualization, dataset inspection, and machine learning experimentation into a unified workflow.
The frontend interface allows users to explore EEG signals, construct datasets, and execute AI models, while the backend handles preprocessing, model execution, and evaluation.

The workflow proceeds as:

signal inspection → dataset verification → model training → evaluation

This ensures that model results are directly connected to verified signal characteristics rather than blindly training on raw data.
\pagebreak

\vspace{1em}
\noindent\textbf{Why is AI suitable for this problem?}

EEG analysis involves high-dimensional temporal signals with complex spatial relationships across electrodes. Manual feature engineering is difficult because:

\begin{itemize}
    \item patterns vary across subjects
    \item noise and artifacts are common
    \item signal distributions change across recording sessions
\end{itemize}
Machine learning models can learn robust mappings from EEG-derived features to behavioral targets more effectively than fixed heuristics.

\vspace{0.5em}
\noindent\textbf{Is the problem large, complex, or always changing?}

Yes.


EEG data presents three major challenges:
\begin{itemize}
    \item Large — continuous multi-channel time series
    \item Complex — spatial-temporal correlations
    \item Non-stationary — signals differ between subjects and sessions
\end{itemize}
Because of this variability, deterministic rule-based systems are unsuitable.

\vspace{0.5em}
\noindent\textbf{Can we accept an answer that’s not 100\% perfect?}

Yes. This is a research system.

\vspace{0.5em}

The system is intended for research experimentation rather than safety-critical decision making.
Model predictions are used as analytical indicators, not medical diagnoses.
Therefore approximate predictions with measurable error are acceptable.

\section{Goal Hierarchy}
\label{sec:goal-hierarchy}

\noindent\textbf{Organizational Goal:} Enable efficient experimentation in EEG machine learning research

\vspace{0.5em}
\noindent\textbf{System Goal:} Provide an interactive platform that links signal inspection with machine learning experimentation

\vspace{0.5em}
\noindent\textbf{User Goal:} Explore EEG signals, construct datasets, train models, and compare results without manual scripting

\vspace{0.5em}
\noindent\textbf{AI Model Goal:} Learn mappings that generalize across subjects for RT prediction (regression) and correctness prediction (classification)

\vspace{1em}
\noindent\textbf{Success Metrics:}
\begin{itemize}
    \item reduced prediction error (e.g., MAE/MSE) for RT
    \item improved correctness prediction (accuracy, F1-score, precision, recall)
    \item consistent performance on unseen subjects
    \item reduced experiment setup time
    \item reproducible experiment workflow
\end{itemize}

\section{Task Requirements Analysis Using AI Canvas}
\label{sec:ai-canvas}

\subsection{AI Task Requirements}
\label{subsec:ai-task-requirements}
\begin{itemize}[leftmargin=3.5em]
    \item \textbf{Requirements (REQ):} Predict behavioral outcomes from prestimulus CCD-ITI EEG segments in HBN-EEG.
    \item \textbf{Specifications (SPEC):} Evaluate models that map CCD-ITI features to RT (regression) and trial correctness (classification).
    \item \textbf{Environment (ENV):} Evaluated on multi-subject EEG datasets with different recording conditions. (e.g., noise, subject variation).
\end{itemize}

\subsection{AI Canvas Summary}
\label{subsec:ai-canvas-summary}
\begin{itemize}[leftmargin=3.5em]
    \item \textbf{Input:} Preprocessed EEG segments
    \item \textbf{Output:} Predicted RT (regression) and predicted correctness (classification)
    \item \textbf{Success Criteria:} Lower RT prediction error and higher correctness classification performance with stable generalization to unseen subjects.
\end{itemize}

\subsection{Innovation}
\label{subsec:innovation}
The system integrates visualization-driven dataset validation with model training inside a single interactive interface, reducing mismatch between inspected signals and training data.

\section{AI Model Development and Evaluation}
\label{sec:model-development-evaluation}

\subsection{Model Development and Training Strategy}
\label{subsec:model-development-strategy}
The modeling workflow is designed to be repeatable and target-aware:
\begin{itemize}
    \item \textbf{Inputs:} preprocessed CCD-ITI epochs and ITI-derived feature tables.
    \item \textbf{Targets:} RT (regression) and correctness (binary classification).
    \item \textbf{Baseline-first approach:} start with simple, interpretable models before considering more complex architectures.
    \item \textbf{Split strategy:} prefer subject-independent splits to evaluate generalization and reduce overly optimistic estimates.
\end{itemize}

\subsection{Testing and Validation Approach}
\label{subsec:testing-validation}
Validation focuses on preventing misleading results caused by data issues or leakage:
\begin{itemize}
    \item sanity checks for trial counts, label distribution, and missing channels,
    \item verification plots (e.g., SNR spectra) to confirm steady-state characteristics,
    \item consistent preprocessing parameters and fixed random seeds,
    \item run logging of dataset filters, split definitions, and model configurations.
\end{itemize}

\subsection{Performance Results and Justification}
\label{subsec:performance-results}
Recent runs were analyzed from exported W\&B logs for both targets (RT regression and correctness classification). The evaluation intentionally avoids selecting a single ``best model'' because each configuration fails in a different way.

Model results are reported using target-appropriate metrics:
\begin{itemize}
    \item \textbf{RT regression:} MAE, RMSE, R², and Pearson correlation.
    \item \textbf{Correctness classification:} accuracy and balanced accuracy, with sensitivity/specificity and confusion-matrix behavior.
    \item \textbf{Training dynamics:} training loss and validation loss across epochs.
\end{itemize}

Observed patterns from the latest runs are:
\begin{itemize}
    \item \textbf{Regression stagnation:} MAE remains narrowly clustered around 0.287--0.288 and R² remains near zero (about 0.003--0.008), indicating weak explanatory power.
    \item \textbf{Mean-prediction tendency:} predicted RT mean is close to true RT mean, suggesting partial collapse toward central tendency instead of learning richer trial-level structure.
    \item \textbf{Imbalance-driven classification failure:} one high-accuracy configuration reaches about 0.729 accuracy but only about 0.501 balanced accuracy, with very high sensitivity and very low specificity, indicating majority-class dominance.
    \item \textbf{Partial mitigation only:} class weighting, weighted sampling, and undersampling improve specificity somewhat, but none provides consistently strong balanced performance.
\end{itemize}

These outcomes justify treating the current AI component as a reproducible experimental baseline rather than a finalized predictive solution.

\section{User Experience Design with AI}
\label{sec:ux-ai}

The platform follows a research-oriented workflow where users first inspect signals before executing machine learning models.
To support this process, the interface uses a \textbf{mode-action} structure, and additionally provides flexible 
\textbf{subject selection and filtering} to accommodate both single-subject inspection and cohort-level analysis.

\vspace{1em}
\noindent\textbf{Interface Overview:}
The interface contains four primary operational modes:

\begin{itemize}[leftmargin=3.5em]
    \item \textbf{Plot Mode:} — detailed single-view signal inspection
    \item \textbf{Grid Plot Mode:} — comparative multi-condition visualization
    \item \textbf{Data Mode:} — structured data inspection and preparation
    \item \textbf{AI Mode:} — machine learning experimentation
\end{itemize}

Each mode exposes only the actions relevant to the selected context, and all user actions are logged to support transparency and reproducibility.

\begin{itemize}
    \item \textbf{Subject Selection and Filtering}
    Users can choose between two primary input types:
    \begin{itemize}
        \item \textbf{Single Subject:} 
        \begin{itemize}
            \item User selects an individual participant and task.
            \item All mode actions are executed for the selected subject only.
            \item This mode is ideal for detailed inspection or troubleshooting of individual EEG recordings.
        \end{itemize}
        \item \textbf{Cohort Filter (Meta Filter):} 
        \begin{itemize}
            \item User defines filters across attributes: sex, age range, attention, internalizing/externalizing scores, CCD accuracy, response time.
            \item Optional ``Per Subject'' toggle for applying filters individually or collectively.
            \item This mode enables exploratory data analysis and large-scale EEG studies without manual participant selection.
        \end{itemize}
    \end{itemize}
\end{itemize}

\vspace{2em}
\noindent\textbf{Visualization and Inspection Modes}

\subsection{Plot Mode}

Provides detailed EEG inspection including sensor layout, time-domain plots, frequency plots, epoch plots, evoked responses, and SNR analysis.

Available actions include:
\begin{itemize}
    \item sensor layout visualization
    \item time-domain signal plots
    \item frequency-domain plots
    \item epoch visualization
    \item evoked response plots
    \item evoked topography plots
    \item SNR spectrum analysis
\end{itemize}

\subsection{Grid Plot Mode}

Allows comparison across conditions using PSD, SNR, and evoked grids.

Available actions include:
\begin{itemize}
    \item PSD Grid
    \item SNR Grid
    \item Evoked Grid
\end{itemize}

\subsection{Data Mode}

Displays structured EEG data tables to confirm dataset composition.

Available actions include:
\begin{itemize}
    \item EEG sample tables
    \item epoch tables
    \item metadata
\end{itemize}

\subsection{AI Interaction Mode}

AI Mode enables machine learning experimentation using the prepared EEG data. The interface provides a set of interrelated actions that support an iterative workflow from dataset construction to model training and analysis.

Available actions include:

\begin{itemize}
    \item Build Dataset
    \item TrainEEGNetMultiRegression
    \item Model Summary
\end{itemize}

\vspace{1em}
\noindent\textbf{System Behavior:}
These actions are interdependent: dataset construction is required before training, and the model summary reflects the structure of the model. Performance metrics are generated during training and updated dynamically.

Logs and outputs are available for inspection and export, supporting transparency and reproducibility.

This design emphasizes transparency by exposing intermediate training metrics directly through logs rather than abstracted summaries.

\vspace{1em}
\noindent\textbf{Feedback Loop:}
inspect → adjust → train → evaluate → compare → refine

Researchers can iteratively adjust dataset configurations,rerun experiments, and retrain models without rewriting scripts or managing computing environments. This significantly shortens the experimental cycle compared to notebook-based pipelines.

\section{Deployment Strategy}
\label{sec:deployment-strategy}

\subsection{Deployment Plan}
\label{subsec:deployment-plan}
The AI component is deployed in a research environment using both local execution and cloud notebooks.

The system consists of:

\begin{itemize}
    \item Frontend — interactive research interface
    \item Backend — REST API service
    \item Model — behavioral prediction model
\end{itemize}

Technologies used:

\begin{itemize}
    \item React — interactive frontend framework
    \item FastAPI — model service endpoints
    \item TensorFlow — neural network execution
    \item scientific Python libraries — preprocessing and evaluation
\end{itemize}


The frontend web system replaces manual notebook execution and allows controlled interaction with the EEG pipeline,
and the backend exposes endpoints for training, prediction, and evaluation, allowing modular integration and testing.

The model in our system targets prestimulus behavioral prediction from CCD-ITI segments by mapping EEG-derived features to reaction time (RT) (regression) and trial correctness (classification).

\section{Proof of Concept (Service Demonstration)}
\label{sec:proof-of-concept}
The pipeline can be exercised end-to-end under a subject-independent evaluation setting.
In this setting, models are trained on a group of subjects and tested on unseen individuals, which better reflects generalization and avoids overly optimistic estimates from within-subject testing.

The system supports the workflow:

visualization → dataset selection → training → inference → evaluation

Results can be accessed through the interface and (when enabled) through API endpoints.

\section{Reflection and Future Development}
\label{sec:reflection}


\subsection*{Lessons Learned}
\begin{itemize}[leftmargin=3.5em]
    \item Prestimulus CCD-ITI segments contain steady-state information that can support behavioral prediction.
    \item A consistent preprocessing and verification workflow improves reproducibility of results.
    \item Integrated workflows reduce experimentation overhead
\end{itemize}


\subsection*{Challenges}
\begin{itemize}[leftmargin=3.5em]
    \item \textbf{Model not completed in time:} The learning procedure still fails to achieve stable performance for correctness classification.
    \item \textbf{Majority-class collapse:} The correctness classifier tends to predict a single class, yielding an accuracy close to chance level (approximately 50\%) while providing limited practical value.
    \item \textbf{Class imbalance:} Correct/incorrect labels are imbalanced in parts of the data, which can bias training and evaluation without careful handling.
    \item \textbf{Data integrity issues:} Evidence of data corruption and trial/label misalignment can cause feature--label shifts, making supervised learning unstable and masking true signal--behavior relationships.
\end{itemize}

\subsection*{Future Work}
\begin{itemize}[leftmargin=3.5em]
    \item \textbf{Fix label reliability:} add dataset-level integrity checks (trial counts, event ordering, and label alignment) and remove or repair corrupted segments.
    \item \textbf{Handle class imbalance:} use stratified splits, class-weighted loss, resampling, and calibration to avoid majority-class collapse.
    \item \textbf{Improve evaluation:} report confusion matrices and class-aware metrics (F1-score, precision, recall) alongside accuracy.
    \item \textbf{Modeling improvements:} explore robust feature sets and temporal models after data alignment is verified.
\end{itemize}
